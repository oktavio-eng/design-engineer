# Changelog

Notable changes to this site, in the order they landed on `main`. Newest first. This is the technical log — for the narrated version, see `/changelog` on the site itself. See `AGENTS.md` for the deeper "why" behind several of these; a few entries below only summarize it.

## 2026-08-29

- Mail composer validates the reply address before it sends. The email step (skippable since 23/08 on purpose) is now a gate: arrow and Enter both go through `advance()` → `validateEmail()` in `mail.js`, and `sendMail()` re-checks before posting. The rule is WHATWG's `input[type=email]` pattern plus at least one dot in the domain (`name@gmail` is a typo, not an address). Blank or malformed → `#mailReplyHint` under the field (`role="alert"`, `aria-describedby`, textarea `aria-invalid`), a ±4px `translate` shake on the step (`.composer__step.is-invalid`, `--duration-320`, off under reduced motion), focus stays; typing clears it. Hint is `--muted`, not red — the palette has no danger token and the site is monochrome by design. A send that fails everywhere now says `Couldn't send — try again.` in `#mailTextHint` instead of a bare `console.error`. Both textareas gain an `aria-label` ("Your email", "Message") — they only had a placeholder for a name, which axe flagged (`label-title-only`) the moment the new test scanned the open sheet. `docs/messages.md` is the topic doc; `tests/ui/mail-composer.test.mjs` runs the real flow on `/` with both destinations intercepted; *Mail composer · email validation* story pins the CSS/a11y of the invalid state. (#82)
- Every sent message is also archived in Supabase: `sendMail()` runs Web3Forms and a plain-REST `POST /rest/v1/messages` (anon key, `Prefer: return=minimal`, no SDK — no bundler) in parallel with `Promise.allSettled`; "sent" when at least one landed, the other's failure goes to the console. `supabase/schema.sql` creates `public.messages` (`id`, `created_at`, `email`, `message`, `page`) with the same email regex as a `CHECK`, RLS on, and a single policy — `anon` may INSERT, no SELECT exists, so the public key in `mail.js` reads nothing back. `SUPABASE_URL`/`SUPABASE_ANON_KEY` ship blank; with either empty the insert is skipped and the composer keeps working through Web3Forms alone. Setup is three dashboard steps in `docs/messages.md`. (#82)
